# API32 reconstruction inputs

The missing diagnostic-ADB stage is now provided as source. The two small
policy helpers can also be regenerated byte-for-byte from qualified local
inputs. No vendor policy, generated mapping, NUL-containing xattr file,
firmware image, GApps package or root credential is distributed here.

**The complete existing CLI pipeline is still not transferable from stock
inputs alone.** The final GNSS builder and verifier require the exact retained
APatch boot, including its owner-specific root-key verifier. Neither consumes
that boot to construct system bytes, but both enforce its hash. This document
does not remove that check or provide a replacement root environment.

## What is supplied

- [Diagnostic ADB builder](../scripts/build_api32_diagnostic_adb_candidate.py):
  the original offline transformation, with a negative-offset rejection added.
  It changes two same-length spans in `init.usb.rc`; their combined 158 changed
  bytes retain the existing `adbd` service, authentication configuration,
  inode, file size and block placement. It does not install or launch ADB.
- [Focused diagnostic tests](../tests/test_build_api32_diagnostic_adb_candidate.py):
  source/span rejection, semantic preservation and complete small-file raw
  comparisons, plus an optional owner-supplied filesystem fixture.
- [Policy-input preparer](../scripts/prepare_api32_reconstruction_inputs.py),
  [source contracts](../fixtures/api32/policy-input-contract.json) and the
  [standard label text](../fixtures/api32/sepolicy-file-context.txt).
  The preparer uses only Python's standard library and performs no downloads,
  image extraction, device I/O or filesystem-image rebuild.
- [Focused preparation tests](../tests/test_prepare_api32_reconstruction_inputs.py).

The preparer is original derivation code. It does not ship the OEM policy or
assume that a generated file inherits a redistribution license. It selects
names declared as both concrete types and versioned `29.0` attributes in the
owner-supplied vendor public policy, subtracts names already present in the
original API29 GSI mapping, sorts the result and generates identity bindings.
The historical four-line comment header is retained because it contributes
to the expected file hash. Its historical diagnostic wording is not a current
runtime claim. The xattr is generated from the standard label text by replacing
its final LF with one NUL byte. No firmware bytes are encoded in these fixtures.

## Offline preparation and stage commands

Use a separate private working copy for reconstruction. Keep downloaded and
generated inputs out of the source release tree and release archives. Set
`DBY_VENDOR_PUBLIC_POLICY`, `DBY_API29_MAPPING`, `DBY_API32_SYSTEM` and
`DBY_STOCK_SUPER` to your existing qualified local files; no command below
contacts a device or obtains firmware. The policy files must first be extracted
locally from the matching images with appropriate filesystem tooling; that
extraction is not implemented by this source-only helper.

From that private working copy's root:

```bash
python3 -B scripts/prepare_api32_reconstruction_inputs.py \
  --vendor-public-policy "$DBY_VENDOR_PUBLIC_POLICY" \
  --api29-gsi-mapping "$DBY_API29_MAPPING" \
  --output-dir analysis/firmware-20261014/api29-aosp-baseline-offline-20261025

python3 -B scripts/build_api32_candidate.py \
  --source-system "$DBY_API32_SYSTEM" \
  --stock-super "$DBY_STOCK_SUPER" \
  --output-dir analysis/firmware-20261014/api32-next-checkpoint-offline-20261027/candidates/build-a

python3 -B scripts/build_api32_diagnostic_adb_candidate.py \
  --output-dir analysis/firmware-20261014/api32-diagnostic-adb-offline-20261027/build-a
```

The minimal builder's [native tool contracts](../scripts/build_api32_candidate.py)
pin the exact `debugfs`, `e2fsck` and `resize2fs` binaries, including their
SHA-256 values and `/opt/homebrew/opt/e2fsprogs/sbin/` locations. The recipes
require the recorded e2fsprogs 1.47.4 behavior, macOS `/bin/cp -c`, the frozen
ext4 layout and timestamp normalization. A matching version label alone is
insufficient to pass the binary hash gate. This package neither ships those
tools nor claims portability to a different host toolchain.

The final command is conditional: it only works for an operator who already
has the exact private retained boot at
`analysis/firmware-20261014/api29-apatch-root-20261025/candidate/apatch-11224-boot.img`.
It is not a way to reconstruct that boot from stock:

```bash
python3 -B scripts/build_api32_system_framework_gnss_1_1_candidate.py \
  analysis/firmware-20261014/api32-system-framework-gnss-1_1-offline-20261028/build-a
```

The [final verifier](../scripts/verify_api32_system_framework_gnss_1_1_candidate.py)
enforces the same boot prerequisite. The framework manifest's accepted hash is
`e1709cc931677e71ac3c51257ac9e207060f95f3449b28ec5f676f992640df07`.

## Remaining gaps and verification boundary

- Supplying matching stock boot plus an independently chosen APatch key will
  not reproduce the owner-bound boot hash. A later, separately reviewed change
  would need to separate offline system construction from that live boot
  control prerequisite; these additions do not bypass it.
- The full super additionally requires the exact recorded stock super and
  layout, not an arbitrary DBY-W09 build. Other regions retain Huawei payloads.
- Native tool acquisition and local input extraction remain operator steps.
  These sources do not constitute a self-contained firmware build environment.
- Exact-target VINTF replay and paired-build qualification require separately
  rebuilt replay evidence and owner-extracted dependencies; constructing a
  byte-identical image alone does not recreate that evidence or prove a boot.

The public tests can be run without firmware or native tools:

```bash
python3 -B -m unittest discover -s tests -p 'test_build_api32_diagnostic_adb_candidate.py' -v
python3 -B -m unittest discover -s tests -p 'test_prepare_api32_reconstruction_inputs.py' -v
```

The optional `DBY_API32_MINIMAL_SYSTEM` test reads only the recorded rc file and
inode/block metadata from a local minimal image through `debugfs`; it does not
rebuild it. The preparation helper was also checked against the two qualified
private policy inputs: both small outputs were byte-identical to the recorded
build inputs, then removed from temporary storage. Synthetic raw-patch tests
use kilobyte-sized files. No multi-GB image build was performed for this change,
so end-to-end reconstruction with this public working tree remains untested.
